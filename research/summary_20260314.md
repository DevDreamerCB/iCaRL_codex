## Effective Methods

Clearly effective:

1. Removing the current supervised contrastive loss.
2. Adding a small task adapter around the embedding output.
3. Using explicit `LwF`.
4. Reweighting old classes with `old_class_weight_power`.
5. Using `normalized NME` for final prototype classification.
6. Giving later stages more optimization with `stage_epochs=[10,12,14]`.

Most important inflection point:

- `normalized NME` changed the geometry of final exemplar classification enough to create the biggest jump in `task3`
- after that, `stage[10,12,14]` produced another stable boost without increasing memory

## Methods That Looked Weak or Negative

These directions are currently not worth more time unless re-implemented from scratch:

- current supervised contrastive loss
- prototype alignment loss
- `embedding_only`
- larger fixed replay batches such as `replaymix4`
- current simple feature distillation
- aggressive later-stage schedules like `[10,14,16]`
- using larger memory as the main improvement story

## Convergence Status

The current best line appears to train normally.

From one representative full-confirm log:

- Stage 2 loss decreases from about `0.845` to `0.691`
- Stage 2 train accuracy rises from about `48.4%` to `59.3%`
- Stage 3 loss decreases from about `0.902` to `0.745`
- Stage 3 train accuracy rises from about `44.6%` to `47.5%`

This suggests:

- no obvious divergence
- later epochs still help, but gains saturate
- stage 3 remains the main bottleneck
- longer schedules help only when applied mildly; more is not automatically better

## Working Hypothesis

The biggest remaining problem is not raw capacity. It is the mismatch between:

- cross-subject feature geometry
- class bias accumulated across stages
- final prototype-based decision boundaries

That is why the best gains so far come from:

- geometry fixes (`normalized NME`)
- lightweight PEFT (`adapter16`)
- forgetting control (`LwF`, old-class weighting)
- schedule changes (`stage[10,12,14]`)

## Next Directions

Highest-priority next directions:

1. `oldweight2.25 + stage[10,12,14]`
   - already the strongest current screen
   - likely best next full confirm candidate

2. Radius-normalized NME
   - classify with prototype distance normalized by per-class exemplar spread
   - this is a lightweight extension of the successful NME geometry line
   - easy to explain in a thesis

3. Bias correction on top of prototype inference
   - not FC-head BiC directly
   - instead a prototype-side calibration or class-age-aware distance correction

4. More principled prototype distillation
   - current simple feature distill is weak
   - if revisited, it should look more like a PODNet-style representation regularizer

## Thesis-Friendly Narrative

A clean thesis story is already emerging:

1. naive contrastive regularization was not helpful in this EEG cross-subject class-incremental setting
2. the key issue was prototype geometry and incremental bias, not backbone size
3. a lightweight combination of `adapter + LwF + old-class reweighting + normalized NME + mild later-stage schedule` gave the best fixed-memory performance
4. the improvement was obtained without modifying the pretrained backbone structure

## AutoResearch Status

The codebase now contains a two-layer local research system:

- executor: `autoresearch_icarl.py`
- agent controller: `agent_loop.py`

The executor runs candidates within the current research family.
The agent controller monitors stagnation and switches research direction automatically.

This is closer to an online research agent than the earlier overnight script, but it still depends on local rules rather than a live chat model.

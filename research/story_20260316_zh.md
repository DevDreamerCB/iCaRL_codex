# iCaRL_codex 研究全过程梳理

日期：`2026-03-16`

## 1. 课题目标

本项目研究的是脑机接口中的跨被试类增量学习，固定场景为：

- `stage1`：训练被试 `1,2,3` 的 `A,B`
- `stage2`：训练被试 `4,5,6` 的 `B,C`
- `stage3`：训练被试 `7,8,9` 的 `C,D`
- 测试依次为 `AB`、`ABC`、`ABCD`

类别映射：

- `A`：左手
- `B`：右手
- `C`：双脚
- `D`：舌头

核心优化目标：

1. 提高 `task2` 总准确率
2. 提高 `task3` 总准确率
3. 尤其关注 `task3` 中旧类 `A/B` 的保持

## 2. 当前最好结果

截至目前，当前最好的正式结果是：

- 运行名：`lwf0175T15_normnmehybrid_s3old04_ptblend02s3new_affine2_adapter16_mem36_oldweight3125_stage101212_stagefd003_taskaffine_s3_confirm`
- 指标：`task1=84.18, task2=60.75, task3=49.36`
- 综合分：`59.74`

这条主线的关键组合是：

- 去掉对比损失
- `LwF(lambda=0.175, T=1.5)`
- `normalized NME`
- `hybrid NME+logits`，且只从 `stage3` 开始启用
- `task adapter(dim=16)`
- `task affine` 从 `stage2` 开始
- `stage3-only feature distillation = 0.03`
- `old_class_weight_power = 3.125`
- `memory = 36`
- `stage_epochs = [10, 12, 12]`
- `new_only stage3 prototype blend alpha = 0.2`

## 3. 探索主线是怎么形成的

### 第一阶段：先把原始 iCaRL 跑通并建立自动化评测

一开始先确认了原始代码逻辑：

- 训练阶段用 `fc logits`
- 最终正式评估主要看 exemplar mean / `NME`

随后补了自动化实验脚本、`metrics/latest.md`、`metrics/experiments.csv`、`research/results.tsv`，形成了固定流程：

- `screen = 1 seed + 10 epoch`
- `confirm = 3 seeds + 30 epoch`

这一步的意义是：后面所有探索不再靠手工比日志，而是统一记录。

### 第二阶段：先扫最便宜的训练策略和轻量模块

最早一批尝试包括：

- 去掉对比损失
- `embedding_only`
- prototype alignment
- task adapter
- prompt / LoRA / BN / affine

这一阶段最重要的结论是：

- 当前这版 `contrastive loss` 在本项目里是负收益
- `embedding_only`、prototype alignment、早期 prompt/LoRA 大多 short 有信号，但 full confirm 不稳

关键里程碑：

- `baseline_confirm`：`85.80 / 59.85 / 37.23`
- `no_contrastive_confirm`：`85.80 / 60.78 / 40.24`
- `no_contrastive_adapter16_s2_confirm`：`85.34 / 61.52 / 41.34`

解释：

- 去掉对比损失是第一个明确有效的变化
- 小 adapter 有帮助，但单靠 adapter 还不够

### 第三阶段：修正训练流程问题，结果开始可信

中间发现过一次重要实现问题：早期某些 `sampler / loader` 行为会影响结论，所以之后重新以修正后的流程为准。

这一步很关键，因为：

- 一些早期看起来“涨了”的方法，重新验证后不再成立
- 后面 `46+` 到 `49+` 的提升，比最早那批结果更可信

### 第四阶段：形成 corrected pipeline 主线

真正稳定有效的主线开始出现于这几个方向的叠加：

- `LwF`
- old-class weighted BCE
- `replaymix2`
- `adapter16`
- `normalized NME`
- 更合理的 stage schedule

代表性结果：

- `lwf015_normnme_adapter16_mem36_oldweight25_confirm`：`86.11 / 59.46 / 44.85`
- `lwf015_normnme_adapter16_mem36_oldweight25_stage101214_confirm`：`84.18 / 60.62 / 46.99`

解释：

- `normalized NME` 是明显的拐点
- 旧类权重和后两阶段更强的正则，显著帮助了 `task3`

## 4. 后期最关键的两个想法

### 4.1 修正 logits 和 NME 的决策器错配

理论动机：

- 训练时主要优化的是 `fc logits`
- 最终报告时却主要使用 `NME`
- 这意味着训练目标与最终分类器并不一致

于是引入了轻量的 `hybrid NME + logits` 校准。

相关思想可参考：

- BiC / Large Scale Incremental Learning  
  https://openaccess.thecvf.com/content_CVPR_2019/html/Wu_Large_Scale_Incremental_Learning_CVPR_2019_paper.html

这条线后来发展为：

- `stage3-only hybrid`
- 再叠加更轻的校准权重

代表性结果：

- `lwf0175T1375_normnmehybrid_s3old04_adapter16_mem36_oldweight325_stage101212_stagefd0025_taskaffine_s3_confirm`
  - `85.72 / 59.65 / 48.70`

解释：

- 这是第一次让 `task3` 在 full confirm 中稳定冲到 `48+`

### 4.2 只修正真正新增类的 prototype

理论动机：

- 全局 prototype blend 容易把旧类结构也扰乱
- 新类更容易因样本少、跨被试偏移大而原型不稳
- 所以更合理的是“只修正新增类”，而不是全局替换

后来形成的最优版本是：

- `new_only stage3 prototype blend`
- 再和 `hybrid`、`task affine from stage2`、`stage3 feature distill` 组合

代表性结果：

- `...ptblend07s3new...`：`84.18 / 60.80 / 48.91`
- `...ptblend02s3new...`：`84.18 / 60.75 / 49.36`

解释：

- 这说明 prototype refinement 不是越强越好
- 最终最优区间在比较小的 `alpha`，说明“轻修正”优于“重替换”

## 5. 重放相关方法是如何探索的

### 已经尝试过的 replay family

1. 左右通道镜像增强 + 标签翻转  
结论：没有超过主线。

2. subject-balanced replay  
包括：
- `subject_kmeans`
- `subject_herding`
- `subject_diverse_herding`
结论：思路来自跨被试多样性，但在本代码库里不如当前主线。

3. `global_kmeans / pca_kmeans` exemplar 选择  
理论来源接近 ReCIL 的“代表性 + 多样性”局部 replay。  
结果：
- `globalkmeans`：`84.72 / 61.50 / 49.50`
- `pcakmeans`：`84.72 / 61.50 / 49.50`
结论：接近，但仍没超过当前 strongest short。

4. `DER-lite / replay logits`  
论文：
- DER / DER++  
  https://papers.nips.cc/paper_files/paper/2020/file/b704ea2c39778f07c617f6b7ce480e9e-Paper.pdf

结果：
- `derlite02s3`：`84.72 / 61.50 / 49.27`
结论：稳定，但不够强。

5. `alignment-memory replay`  
思路来自 ReCIL 中“global replay of alignment information”的启发。  
论文：
- ReCIL（本地 PDF）  
  [2025_CS-CIL_TBME_Yang.pdf](/data1/bochen/cbcontinual/iCaRL_codex/2025_CS-CIL_TBME_Yang.pdf)

结果：
- `replaygea_s3`：`84.72 / 61.50 / 49.54`
- `replaygea_s2`：`84.72 / 59.57 / 39.89`
结论：
- 只从 `stage3` 开始有一定价值
- 提前到 `stage2` 明显有害

6. `hard replay / MIR-lite`

理论来源：

- MIR: Maximally Interfered Retrieval  
  https://papers.nips.cc/paper_files/paper/2019/hash/15825aee15eb335cc13f9b559f166ee8-Abstract.html

实现方式：

- 不做完整 look-ahead MIR
- 而是用“当前模型和存储 logits 的失配程度”作为 replay 采样权重

结果：

- `hardreplay05s3`：`84.72 / 61.50 / 49.58`
- `hardreplay10s3`：`84.72 / 61.50 / 49.58`
- full confirm：目前与当前最好 full 基本持平，没有明显突破

结论：

- 这条线是当前 replay family 里比较强的一条
- 但还没有真正超过最优主线

7. `RAR-lite / repeated rehearsal`

理论来源：

- RAR: Repeated Augmented Rehearsal  
  https://arxiv.org/abs/2209.13917

当前结果：

- 第一版 short 大约只到 `49.07`

结论：

- 目前这版偏弱，暂时不保留

## 6. 已验证有效与已基本证伪的方法

### 已验证有效

- 去掉对比损失
- `LwF`
- old-class weighted BCE
- `normalized NME`
- `task adapter dim=16`
- `task affine`
- `stage3-only feature distillation`
- `hybrid NME + logits`
- `new_only stage3 prototype blend`

### 已基本证伪或暂不优先

- 当前实现下的对比损失
- `embedding_only`
- prototype alignment
- task BN
- 多数 prompt / LoRA 变体
- 左右镜像 replay 增强
- subject-balanced replay 选样
- PCA herding
- age-NME / radius-NME / FeCAM 风格协方差距离
- 当前这版 `RAR-lite`

## 7. 为什么最近几轮越来越像“局部微调”

因为从实验现象看，主线已经逐步逼近平台区：

- 大改结构通常不如轻量校准
- replay 选样继续换花样，收益已经很有限
- 当前更有效的是：
  - 精确修正 `task3` 的决策偏置
  - 只对新增类做局部 prototype refinement
  - 在不破坏 `task2` 的前提下维持 `task3`

所以最近几轮虽然看起来像调参，但本质上是在已经形成的有效主线上做局部最优搜索。

## 8. 未来最值得继续做的方向

### 方向一：更正规的 MIR，而不是当前的 MIR-lite

当前 `hard replay` 只是近似版，真正的 MIR 还没完整做。

适合原因：

- 仍然属于 replay usage，不改 backbone
- 目标直指旧类保持

### 方向二：更强的 alignment-memory replay

目前只做了很轻的 stage3 global EA replay。

可继续方向：

- alignment-memory replay 和 prototype refinement 的联合设计
- 更明确地区分“原型记忆”和“对齐记忆”

### 方向三：更规范的 bias correction

虽然已经有 `hybrid` 和 `group-bias`，但 still 有空间。

可参考：

- BiC  
  https://openaccess.thecvf.com/content_CVPR_2019/html/Wu_Large_Scale_Incremental_Learning_CVPR_2019_paper.html

### 方向四：面向 EEG 的 subject-invariant prototype regularization

要点：

- 不直接做重模型改造
- 只在 prototype 或 feature geometry 上做跨被试约束

### 方向五：固定 memory 下的“性能-成本 Pareto”

当前最优主线是 `mem36`，但后面完全可以整理出：

- `mem24`
- `mem30`
- `mem36`

三档结果，作为论文里非常好解释的一组实验。

## 9. 一句话总结

整个探索过程不是“不断乱试很多模块”，而是逐步收敛成了这条逻辑：

1. 先修训练策略
2. 再修旧类保持
3. 再修 `NME` 几何
4. 最后修 `logits` 与 `NME` 的决策器错配
5. 在此基础上，只对真正新增类做轻量 prototype refinement

当前最强故事线已经比较完整，后续工作重点不再是大改 backbone，而是把 replay、prototype、bias calibration 这三者的关系做得更稳、更好解释。
